## 1. Репозиторий

Код лежит в репозитории разработчика. Два способа передать его заказчику:

**Вариант А — передать репозиторий целиком (вся история коммитов сохраняется):**

1. GitHub → репозиторий → **Settings** → в самом низу **Transfer ownership**.
2. Ввести имя пользователя или организации заказчика.
3. Заказчик подтверждает перенос по письму.

После переноса нужно заново связать проект с Vercel (см. п.2), потому что
адрес репозитория изменится.

**Вариант Б — отдать копию:**

Если заказчику git не нужен, достаточно архива: GitHub → **Code** → **Download ZIP**.
Либо заказчик создаёт пустой репозиторий у себя и разработчик делает push.

## 2. Хостинг (Vercel)

Проект развёрнут на Vercel и подключён к GitHub: каждый push в `main`
автоматически обновляет сайт.

**Как передать доступ:**

- **Простой путь** — Vercel → проект → **Settings** → **Members** → пригласить
  заказчика по email с ролью **Owner**. Заказчик принимает приглашение,
  после чего разработчика можно удалить.
- **Полный путь** — заказчик заводит свой аккаунт Vercel, импортирует
  репозиторий (**Add New → Project**), добавляет переменные окружения из
  таблицы ниже и нажимает Deploy. Старый проект удаляется.

Тариф: на текущей нагрузке хватает бесплатного. Платный (~$20/мес) нужен,
если вырастет трафик.

## 3. Переменные окружения

Задаются в Vercel: **Settings** → **Environment Variables**.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `FASHN_API_KEY` | Да, для реальной примерки | Ключ AI-модели. Без него сайт работает в демо-режиме |
| `NEXT_PUBLIC_SITE_URL` | Желательно | Адрес сайта для sitemap.xml и ссылок при шаринге |
| `FASHN_MODEL` | Нет | Модель примерки, по умолчанию `tryon-v1.6` |
| `RATE_LIMIT_MAX` | Нет | Сколько примерок с одного IP за окно, по умолчанию 6 |
| `RATE_LIMIT_WINDOW_MS` | Нет | Длина окна в миллисекундах, по умолчанию 60000 |
| `TRYON_TIMEOUT_MS` | Нет | Предел ожидания одной генерации, по умолчанию 55000 |
| `DEMO_DELAY_MS` | Нет | Задержка заглушки в демо-режиме |

После изменения переменных нужен передеплой: Vercel → **Deployments** →
последний деплой → **Redeploy**.

## 4. Аккаунт AI-модели

Ключ выпускается в кабинете FASHN: https://app.fashn.ai → **Settings** → **API**.

Важно: ключ выдаётся только после пополнения баланса. Минимальное пополнение —
**$7.50 (100 генераций)**, кредиты действуют 12 месяцев. Нужен именно раздел
**Developer API**, а не подписка на приложение — это разные кошельки.

Счёт за генерации приходит владельцу аккаунта, поэтому аккаунт стоит сразу
оформлять на заказчика.

## 5. Что сделать перед публичным запуском

Проект готов технически, но перед рекламой и реальными посетителями осталось:

1. **Заменить фото каталога** на снимки товаров заказчика. Сейчас там
   фотографии с Unsplash (свободная лицензия) — они годятся для демонстрации,
   но это не товары заказчика. Инструкция — в README, раздел «Как заменить каталог».
2. **Проверить казахский перевод** у носителя языка: перевод сделан
   разработчиком и не проходил редактуру.
3. **Подключить свой домен** вместо адреса на `vercel.app`:
   Vercel → **Settings** → **Domains**.
4. **Включить ограничение частоты на уровне платформы** (Vercel WAF), если
   ожидается рекламный трафик. Встроенный лимит работает в памяти процесса и
   не защищает от распределённой атаки — см. [lib/rate-limit.ts](../lib/rate-limit.ts).
5. **Решить вопрос с модерацией**: сайт публичный и без регистрации. Сейчас
   модерация выполняется на стороне модели, загрузки не сохраняются.

## 6. Проверка после передачи

Заказчик может убедиться, что всё работает, не будучи разработчиком:

1. Открыть сайт, загрузить фото, выбрать вещь, нажать «Примерить».
2. Результат должен появиться за 10–30 секунд и скачиваться.
3. Плашки «Демо-режим» быть не должно — если она есть, значит `FASHN_API_KEY`
   не задан или задан неверно.

Для разработчика есть одна команда, прогоняющая все проверки:

```bash
npm run verify
```

Она запускает линтер, проверку типов, 130 автотестов и сборку. Те же проверки
выполняются автоматически при каждом push — см. [.github/workflows/ci.yml](../.github/workflows/ci.yml).
